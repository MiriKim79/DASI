## 브랜드 언어

서비스명은 **"다시"** (DASI 아님 — 저장소 슬러그만 기술적 제약으로 DASI 유지). 태그라인 패턴: **"기억을 다시. 그 시절을 다시. 그때의 사람과 다시."** 기능별 카피는 이 언어 안에서 변주한다. 새 UI 카피를 쓸 때 참고:

| 기능 | 카피 예시 |
|---|---|
| 나이 맞히기 | "기억을 다시 꺼내볼까요?" |
| 추억 놀이터 | "그 시절을 다시" |
| 세대별 챗봇 | "2000년대의 누군가와 다시 만나기" (세대에 맞춰 연도 교체) |

시작 화면의 확정 카피("내가 네 나이 맞혀볼게", "쫄리면 패스하기")는 그대로 유지하고, 위 브랜드 언어는 그 외 화면의 부제/전환 문구 등에 보조적으로 사용한다.

## 공통 규칙

- API 응답 필드: **snake_case** (FastAPI/Pydantic 기본값)
- 에러 응답: FastAPI 기본 형식 `{ "detail": "메시지" }` 그대로 사용
- API 경로: `/api` 프리픽스 통일
- 인증: `Authorization: Bearer <JWT>` 헤더
- FE: 모든 화면에서 로딩 / 데이터 없음 / API 실패 / 인증 만료(401→로그인 이동) 4가지 상태 구분
- **클라이언트는 원본 입력(답변/선택지 등)만 전송하고, 최종 나이/점수는 항상 서버가 계산한다.** 클라이언트가 계산된 값을 직접 보내 저장시키는 API는 두지 않는다

## F1. 나이 맞히기 — 1번 (@minkyung3038)

**정신연령은 별도로 두지 않는다. "예상 나이" 하나로 통일.**

### F1-1. 질문 목록 조회 API — [#2](../../issues/2)
- `GET /api/age-test/questions`
- 응답 예: `[{ "id": 1, "text": "...", "options": [{ "id": 1, "text": "..." }] }]`
- 대표나이(age)/가중치(weight)는 서버 내부용, 응답에는 노출하지 않음
- 완료조건: 10문항(경험형7+앵커3)이 순서대로 반환된다

### F1-2. 답변 제출 API — [#4](../../issues/4)
- `POST /api/age-test/submit`
- 요청: `{ "answers": [{ "question_id": 1, "option_id": 2 }, ...] }` (10개)
- 응답: `{ "estimated_age": 27, "top_reasons": ["...", "...", "..."] }`
- JWT가 있으면 이 요청 안에서 **서버가 계산한 값 그대로** 결과까지 저장한다(F1-4 참고) — 클라이언트가 별도로 나이 값을 보내 저장을 요청하는 API는 없다
- 완료조건: 10개 답변 제출 시 예상 나이/결정적 답변 TOP3가 반환된다

### F1-2a. 나이 추정 로직 — [#5](../../issues/5) (#6은 통합되어 closed)
- `estimated_age = Σ(선택지 대표 나이 × 질문 가중치) / Σ(질문 가중치)`, 반올림 1세 단위
- 경험형 질문(7개, "당시 직접 사용/경험했는가" 중심)이 세대를 잘 구분할수록 가중치를 높게, 앵커 질문(3개)은 기준점 보정에 사용
- 결정적 답변 TOP3(`top_reasons`)도 이 로직에서 산출

### F1-3. 검증 — [#7](../../issues/7)
- 10~50대+ 가상 사용자 데이터로 estimated_age 일치율/±2세/±3세/MAE 측정 후 가중치 튜닝
- 완료조건: 검증 리포트 기준 가중치가 1차 확정된다

### F1-4. 결과 저장 (F1-2에 통합) — [#9](../../issues/9)
- 별도의 저장 엔드포인트를 두지 않는다 — F1-2(`POST /api/age-test/submit`) 처리 중 JWT가 있으면 서버가 방금 계산한 값을 그대로 저장한다
- 클라이언트가 estimated_age 값을 직접 실어 보내는 저장 요청은 만들지 않는다 (위변조 방지)
- 완료조건: 로그인 상태로 제출하면 서버가 계산한 결과가 DB에 저장되고, 비로그인 상태로 제출해도 계산 결과는 정상 반환된다(저장만 생략)

### F1-5. 화면 — [#1](../../issues/1) [#3](../../issues/3) [#8](../../issues/8) [#10](../../issues/10)
- 시작 화면(#1, "쫄리면 패스하기") → 퀴즈 진행(#3, 진행률 표시) → 결과 화면(#8, 예상 나이/TOP3/다시하기/메인이동) → 패스(#10, 메인 바로 이동)
- 결과 화면에서 **비로그인 상태**면 "결과를 저장하거나 공유하려면 로그인하세요" 같은 로그인 유도 문구 + 로그인 이동 버튼을 함께 보여준다 (#8). 공유 자체는 별도 기능으로 정의된 게 없어 문구상의 표현이며, 실제 공유 버튼이 필요하면 별도 이슈로 추가한다

### F2-2. 분야별 퀴즈 API — [#16](../../issues/16) [#17](../../issues/17) [#18](../../issues/18)

**[확정 — 2026-08-11] 추억 놀이터 8개 분야: 게임 · 드라마 · 영화 · 애니·만화 · 문방구·놀이 · 유행어·밈 · 먹거리 · 음악.** 개그는 추억 놀이터에 노출하지 않고 챗봇(F3-4)에서만 다룬다 — 기존에 "개그 제외 7개"였던 자리를 게임이 채워 8개 분야가 됐다.

- `GET /api/playground/categories` → `[{ "id": 1, "name": "드라마" }, ...]` (게임 포함 8개, 개그는 제외)
- `GET /api/playground/categories/{id}/quiz` → `{ "category": "드라마", "questions": [{ "id": 1, "text": "...", "options": [...] }] }` (정답은 응답에 포함하지 않음)
- `POST /api/playground/categories/{id}/submit` → 요청 `{ "answers": [{ "question_id": 1, "option_id": 2 }, ...] }` → 응답 `{ "score": 8, "total": 10 }` — 클라이언트는 선택한 answers만 보내고, 서버가 채점해 score를 계산한다
- 서버는 category 존재 여부와 option_id가 해당 질문 소속인지 검증 후 채점한다
- 정답은 제출 **전**(quiz 조회 응답)에는 내려주지 않는다. 제출 **후**(submit 응답)에는 복습을 위해 문항별 정답을 포함할 수 있다 — 예: `{ "score": 8, "total": 10, "results": [{ "question_id": 1, "correct_option_id": 2 }] }`
- 완료조건: 7개 분야 퀴즈를 풀고 점수와 정답 리뷰를 받을 수 있다

## F4. 회원 / 랭킹 / 피드백 — 4번 (@junghocomputer)

### F4-1. 인증 API — [#38](../../issues/38) [#39](../../issues/39) [#40](../../issues/40)
- `POST /api/auth/signup` → `{ "email": "...", "password": "..." }` → `201`
- `POST /api/auth/login` → `{ "email": "...", "password": "..." }` → `{ "access_token": "...", "token_type": "bearer" }`
- 로그아웃은 별도 서버 API를 두지 않는다. JWT는 stateless이므로 **클라이언트가 저장된 토큰을 삭제**하는 것으로 처리한다 (서버 측 블랙리스트 등은 MVP 범위 밖)
- 완료조건: 회원가입 후 로그인하면 JWT가 발급되고, 로그아웃 시 클라이언트에서 토큰이 제거되어 인증이 필요한 요청이 거부된다

### F4-2. 인증 의존성 — [#41](../../issues/41)
- FastAPI `Depends(get_current_user)` 형태로 제공, 다른 라우터에서 재사용
- 완료조건: 1번/3번이 이 의존성을 import해서 로그인 여부를 확인할 수 있다

### F4-3. 랭킹 API — [#37](../../issues/37) [#42](../../issues/42) [#43](../../issues/43) [#44](../../issues/44)

**[변경 — 2026-08-12] 랭킹 = 분야 구분 없는 통합 "랭킹 도전" 하나.** 분야별 개별 랭킹(개그 포함)은 만들지 않는다. 추억 놀이터 8개 분야(게임·드라마·영화·애니만화·문방구놀이·유행어밈·먹거리·음악)에서 **분야당 2~3문제씩 랜덤으로 뽑아 총 20문제**를 구성하고, 그 **정답률**로 전체 사용자 순위를 매긴다. 개그(챗봇)와 나이맞히기(age-test)는 랭킹 대상에서 제외한다(개그가 빠지는 건 이번 변경, 나이맞히기 제외는 기존 결정 유지).

- `POST /api/ranking/challenge` (JWT) — 코인 **10개 차감** 후, 8개 분야의 랭킹 전용 문제 풀(`Content.ranking_enabled = true`)에서 분야당 2~3문제씩 랜덤으로 뽑아 총 20문제를 반환한다(정답 미포함)
- `POST /api/ranking/challenge/submit` (JWT) → 요청 `{ "answers": [...] }`(20문제) → 채점 후 `ranking_records`에 `{ correct_count, total_count: 20, accuracy }` 저장. 서버가 채점하며 클라이언트가 정답 수·정답률을 직접 보내거나 조작할 수 없다
- 20문제를 전부 제출(완료)하면 코인 **+5** 지급 (서버가 완료 여부를 판단해 지급, 클라이언트가 값을 보내지 않음)
- 정렬 기준: **정답률(accuracy) → (동점 시) 정답 수 → (동점 시) 풀이 시간**
- 공식 랭킹 반영은 **하루 1회**로 제한한다(기존 정책 유지). 코인이 있으면 추가로 더 도전할 수 있지만(연습), 연습 기록은 `ranking_records`에 저장하지 않는다
- `GET /api/ranking` → `[{ "rank": 1, "user": "...", "correct_count": 18, "total_count": 20, "accuracy": 0.9 }, ...]` — 분야 파라미터 없음(통합 랭킹 하나뿐)
- **상위 5명까지만 반환한다 (MVP). 추후 상위 10명으로 확대 예정** — 이 확장은 코드가 아니라 조회 API의 limit 값만 바꾸면 되므로 별도 이슈로 가볍게 처리 가능
- 완료조건: 랭킹 도전(20문제) 결과가 정답률 기준으로 정확히 집계·정렬된다

**개그(F3-4)는 랭킹 대상에서 완전히 빠진다.** 챗봇 개그 퀴즈의 정답 판정은 계속 3번 백엔드가 하지만, 더 이상 랭킹 API에 점수를 제출하지 않는다 — [#36](../../issues/36) "개그 퀴즈 점수 → 랭킹 API 제출 연동"은 이 변경으로 보류/취소한다. 같은 이유로 일반 퀴즈 프리플레이 점수도 랭킹에 반영하지 않는다는 기존 결정([#21](../../issues/21) 관련)을 재확인한다.

### F4-4. 피드백 API — [#45](../../issues/45) [#46](../../issues/46)
- `POST /api/feedback` (JWT) → `{ "content": "..." }`
- `GET /api/feedback` → `[{ "id": 1, "user": "...", "content": "...", "created_at": "..." }]`
- 방명록 요구사항은 피드백 기능이 그대로 수행한다(별도 방명록 기능 없음). 등록 전 욕설·비방 표현 필터링(금칙어 필터 + 글자 수 제한)을 거친다

### F4-5. 코인 시스템 — [변경 — 2026-08-12, 이슈 미생성]
- `users.coin_balance` (int, default 0)
- 지급(서버가 판단해 지급, 클라이언트가 값을 보내지 않음): **회원가입 완료 +10**(신규) / 나이맞히기 완료 **+20** / 분야별 일반 퀴즈 최초 완료 **+5**(분야당 1회만) / 랭킹 도전(F4-3) 20문제 전부 완료 **+5**(신규) / 코인 충전(데모, 가상) **+100**
- 차감: 랭킹 도전(F4-3) 시작 **−10**
- 상단바 UI: 로그인 상태면 우측 "로그인" 버튼 자리에 **[코인 개수] [닉네임]** 순서로 표시(코인이 닉네임보다 왼쪽). 비로그인 상태면 상단바 우측에 "회원가입하면 10코인을 드립니다" 문구를 노출한다
- `GET /api/me/coins` → `{ "coin_balance": 120 }`
- `POST /api/me/coins/charge` (데모용) → 가상 코인 +100 지급. **실제 결제 연동은 하지 않는다**
- 코인 사용처 확장(힌트, 특별 퀴즈팩, 모리 의상/액세서리 등)과 실제 결제는 이번 MVP 범위 밖 — 발표자료 부록 슬라이드로만 남기고 이번 스프린트에서는 구현하지 않는다
